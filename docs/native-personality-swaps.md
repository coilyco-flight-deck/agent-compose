# Native personality swaps

The host roster encourages a directly steered native agent to propose a
temporary catalog personality or meld when that change would materially
improve the current task.

## Eligibility

The policy applies only when every condition is true:

* The agent runs in an unwarded native host harness.
* Kai is steering the session interactively, and live interaction is certain.
* No explicit slash goal is active.
* The work is not staged, containerized, headless, unattended, long-burn, or
  async.
* The candidate personality materially helps the current task.

The agent's role, obligations, permissions, and authority remain fixed.
Compiled and native-skill bundles retain the caller-selected personality set.

## Confirmation

The agent names the candidate and reason, then asks a separate question:

> This task would benefit from the <X> persona because <reason>. Should the
> agent swap to it now?

The original task request does not count as confirmation. The agent waits for
an explicit yes before loading every newly active definition, announcing the
temporary swap, and continuing the same task. A decline keeps the current meld,
and the agent continues the task.

## Lifetime

Confirmation covers only the current interactive task. Task completion
restores the role's default meld. Every later swap needs a new proposal and
confirmation.
